# entity (evaluation)

## Overview
JPA entities for the `evaluation` and `answer` tables. Unlike the legacy assessment entities, their ids are generated by the database.

## Interface
- `data class EvaluationEntity` (`@Table(name = "evaluation")`): `id: Long?`, `studentName`, `studentRegistration`, `examCode`, `examTitle`
  - `EvaluationEntity.fromDomain(evaluation: Evaluation): EvaluationEntity`
- `data class AnswerEntity` (`@Table(name = "answer")`): `id: Long?`, `evaluationId: Long`, `questionNumber: Int`, `chosenOption: String`
  - `AnswerEntity.fromDomain(evaluationId: Long, answer: Answer): AnswerEntity`

## Invariants
- Both ids use `@GeneratedValue(strategy = IDENTITY)`, so each insert runs as soon as the entity is saved.
- Every column has an explicit `@Column(name = ...)` matching the snake_case table columns.
- `AnswerEntity` holds a plain `evaluationId` with no JPA relation and no cascade, so saving answers stays a separate step.
- The tables are not created by Hibernate (`ddl-auto: none`). Tests create them from `application/src/test/resources/evaluation-schema.sql`, which also declares the `fk_answer_evaluation` foreign key and the `uq_answer_evaluation_question` unique constraint.

## Side Effects
- None
